# v2.2 收费确认流程 · 提醒设置

## 一、收费确认

工程师认领工单后判断这张单要不要收费。

| 步骤 | 谁来做 | 做什么 | 之后通知谁 |
| --- | --- | --- | --- |
| 1 判断 | 负责工程师 | 选「不收费」或「需要收费」（写原因） | 要收费 → 报价的销售 |
| 2 报价 | 销售 | 填金额、说明；也可以改成「不收费」 | 销售总监；不收费 → 工程师 |
| 3 审核 | 销售总监（岗位为「销售主管」的账号） | 同意并选「已付款 / 未付款，先服务」；或退回销售 | 售后主管；退回 → 销售 |
| 4 确认 | 售后主管 | 确认，或退回上一步 | 工程师、销售、销售总监 |

- 销售提的单，报价固定交给提单的销售；其他人提的单，工程师自己选一位销售。销售总监可以代报价。
- 收费确认进行中（第 2～4 步没走完）：工程师不能「开始处理」「到场打卡」「提交完工」；已经在现场的，离场卡照常打。
- 售后主管确认后，服务价格按报价金额自动记下；选「不收费」且还没定价的，记为保内免费（0 元）。
- 工程师看不到金额、报价说明和销售总监意见；微信提醒里也不出现金额。
- 每一步都写进工单的状态记录。
- 公司没有在职的销售总监时，报价后直接到售后主管。
- 新版小程序（2.2.0）提交完工前必须判断过要不要收费；旧版不受影响。

接口：`POST /api/orders/{id}/charge/decide | quote | review | confirm`，`GET /api/orders/charge-todos`，`GET /api/sales`；
工单详情多一个 `charge` 字段。

## 二、提醒设置

小程序「我的 → 提醒设置」：上面是微信通知授权，下面按类别选择要打开哪些提醒。

| 类别 | 包含 |
| --- | --- |
| 指派与转交 | 工单指派 / 改派给你、转交给你、被加为协助人、新工单待指派 |
| 申请与审批 | 暂停 / 协助 / 升级服务方式的申请待审批，以及同意或驳回的结果 |
| 进度与验收 | 工单待验收、完工被退回、暂停与恢复、已闭环 |
| 收费确认 | 等你报价 / 审核 / 确认，收费确认的结果和退回 |
| 注册申请 | 有新同事申请注册（只有有注册审批权限的人能看到这一项） |

关掉的类别不再发到本人微信；工单记录和首页待办不受影响。设置存在服务器上，换手机也一样。

接口：`GET /api/me/notices`，`PUT /api/me/notices { key, on }`。
