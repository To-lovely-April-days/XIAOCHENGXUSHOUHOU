# v2.1 每日工作内容；维修登记表跟着服务方式走

## 每日工作内容

工程师认领后按天写「今天做了什么」。同一张单、同一个人、同一天一条；**当天可改，过了当天不能改**；只写文字。负责人和协助人各写各的。

- 表 `WorkLogs`（OrderId, EngineerId, Date, Content ≤1000, CreatedAt, UpdatedAt；三者唯一）。迁移 `V21_WorkLogs`。
- `POST /api/orders/{id}/work-logs` `{content}`：本单负责人 / 协助人，工单在待启动 / 处理中 / 暂停搁置。同一天再调 = 修改。
- `OrderDetail`：`workLogs`（日期新的在前）、`canWriteWorkLog`、`myTodayWorkLog`。不新增 action。
- **卡住的位置**
  - 上门：`POST /api/punches` 离场打卡，`formVersion: 2` 时当天还没写且 `workContent` 为空 → `40000 请先填写今天的工作内容`。`workContent` 给了就写成 / 更新当天的记录。一天多次进出只有第一次离场必须写。`GET /api/punches/context` 返回 `todayWorkContent`。
  - 所有服务方式：提交完工（`formVersion: 2`）时负责人在本单至少有一条，或本次带 `workContent` → 否则 `40000 请填写工作内容`。
  - 旧版客户端（不传 `formVersion`）不受影响。

## 维修登记表跟着服务方式走

- 现场维修登记表只属于上门工单，返厂维修登记表只属于返厂工单（升级为返厂后才出现返厂登记表的上传位置）；远程没有登记表。
  添加附件 / 建单 / 改类别时类型与服务方式不符 → `40000 现场维修登记表只能在上门服务的工单里上传` / `返厂维修登记表只能在返厂维修的流程里上传`。
  旧版客户端的 `RepairForm` 不拦，仍按服务方式归类。
- 小程序：通用的「添加附件」和建单页类别里不再有这两张表。上传位置在流程里 ——
  上门：「打卡记录」页签顶部的「现场维修登记表」卡片；返厂：「返厂流程」页签顶部的「返厂维修登记表」卡片（销售 / 主管在「进度」页签看到同一张卡片）。
  「附件资料」里登记表分组只读，标「在流程里上传」。提交完工页仍会检查，没传可在那一页补传。
- 电脑后台：建单类别里去掉两张表；工单抽屉里登记表分组只在对应服务方式显示；抽屉新增「每日工作」。
