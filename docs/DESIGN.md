当前版本 **v1.2**：在 v1.1（价格改由主管定 §9、暂停搁置带原因与审批 §3、多人协作 §10、返厂流程 §11）之上，新增工单附件与工单文件中心（§12）。

## 1. 总体架构

```
售后小程序/
├── docs/                 设计、接口契约、原型
├── miniprogram/          微信小程序（原生 WXML/WXSS/JS，无构建步骤）
└── server/               .NET 8 Web API（ASP.NET Core + EF Core，默认 SQLite，可切 SQL Server/MySQL）
```

- 小程序：原生框架，基础库 ≥ 3.0。自定义 tabBar（按角色显示不同按钮）。
- 后端：ASP.NET Core 8 Web API，JWT 认证，EF Core 8，默认 SQLite（零配置可跑），文件存本地 `uploads/` 并以静态文件提供（文档类附件另有带鉴权的下载接口）。
- 主管电脑后台（原型第 17 页，1440 宽）：纯静态网页 `server/src/Huotong.AfterSales.Api/wwwroot/admin/`（Vue 3 全局构建、无构建步骤），由后端托管在 `/admin/`，仅主管可登录。

## 2. 角色

| 角色 | Role 值 | 小程序底部导航 | 能做什么 |
|---|---|---|---|
| 售后工程师 | `Engineer` | 首页 / 工单(大厅) / **打卡**(中间凸起) / 工时 / 我的 | 认领、预约、到场离场拍照打卡、完工提交、新建工单(客户直联)；作为负责人可申请暂停、申请协助人、记录返厂节点；作为协助人可查看与打卡；作为建单人 / 负责人 / 协助人可给工单加附件。**看不到任何价格，也看不到「仅销售和主管可见」的附件** |
| 销售 | `Sales` | 首页 / 工单(全部，只读) / **新建** / 我的 | 新建工单（不填价格）、跟踪自己提交的工单、查看全部工单(只读)、查看价格并提价格建议、返厂单记录客户寄出 / 客户签收、给自己建的工单加附件（可设「仅销售和主管可见」） |
| 售后主管 | `Supervisor` | 首页(时间轴+待办) / 工单(全部) / **新建** / 我的 | 指派/改派、增减协助人、定价/改价、作废、暂停搁置/恢复、审批暂停与协助人申请、退回、确认闭环、补录打卡、返厂全部节点、导出、账号管理、管理任何工单的附件（添加 / 删除 / 改可见范围）、电脑后台的工单文件中心 |

账号由主管在后台登记（姓名、手机号、角色、部门）。首次使用：微信登录 → 手机号快速验证 → 按手机号匹配员工 → 绑定 openid → 设置头像（可跳过）。之后自动登录。更换微信需主管解绑。

## 3. 工单状态机

| 状态 | 值 | 中文 | 进入方式 |
|---|---|---|---|
| 待认领 | `Pending` | 待认领 | 新建工单后发布到工单大厅 |
| 待启动 | `Accepted` | 待启动 | 工程师认领 / 主管指派 |
| 处理中 | `InProgress` | 处理中 | 现场单：任一参与人首次到场打卡自动进入；远程单：负责人点「开始处理」；返厂单：记录「工厂收货」自动进入 |
| 暂停搁置 | `OnHold` | 暂停搁置 | 主管从「待启动 / 处理中」直接暂停，或同意负责工程师的暂停申请；必须选原因；恢复后回到暂停前的状态 |
| 待验收 | `Submitted` | 待验收 | 负责工程师提交完工 |
| 已闭环 | `Closed` | 已闭环 | 主管确认闭环（存在未补录的缺卡、或尚未定价时禁止） |
| 已作废 | `Voided` | 已作废 | 主管从「待认领/待启动」作废 |

允许的流转：
- Pending → Accepted（claim / assign）；Pending → Voided（void）
- Accepted → InProgress（首次到场打卡 / start / 返厂单记录工厂收货）；Accepted → Voided；Accepted → OnHold（hold）；Accepted 改派（assignee 变更，状态不变）
- InProgress → Submitted（complete）；InProgress → OnHold（hold）；InProgress 改派
- OnHold → 暂停前的状态 Accepted / InProgress（resume）；OnHold 改派
- Submitted → InProgress（reject，退回处理中）；Submitted → Closed（close）

### 暂停搁置（v1.1）
- 原因必选：`WaitCustomer` 等客户 / `WaitParts` 等备件 / `WaitThirdParty` 等第三方 / `Other` 其他；可加说明（选「其他」时必填）。展示文字：`等备件：轴承预计周五到`。
- 主管可在「待启动 / 处理中」直接暂停；负责工程师只能**申请**暂停（同样选原因），主管同意后才进入暂停，驳回可附回复。每张工单同时只有一条待审批的暂停申请。
- 申请会通知主管，并出现在主管首页待办与电脑后台的「待审批申请」里；工程师可撤回；工单状态或负责人变化使申请失去意义时系统自动撤销。
- 有人（负责人或协助人）正在现场计时时不能暂停，须先离场打卡。
- 暂停期间：不能打卡、不能开始处理、不能提交完工，提示「工单已暂停搁置，恢复后才能…」。
- 恢复：回到暂停前的状态（待启动或处理中）。

每次流转写一条状态记录（StatusLog）：操作人、动作文字、时间、目标状态。示例文字：`王敏 建单`、`王敏 建单 · 紧急`、`李工 认领 → 待启动`、`赵主管 指派给 王工 → 待启动`、`李工 首次到场 → 处理中`、`李工 提交完工 → 待验收`、`赵主管 补录离场 18:20`、`赵主管 确认闭环 → 已闭环`。

状态记录带类别（`kind`）：`Status` 状态流转、`Price` 价格（工程师不可见）、`Hold` 暂停、`Assist` 人员、`Factory` 返厂、`Attachment` 附件、`AttachmentPrivate` 受限附件（工程师不可见）。
v1.2 新增的记录文字示例：`王敏 上传附件 现场铭牌.jpg、故障视频.mp4`、`王敏 上传附件 报价单.pdf（仅销售和主管可见）`、`李工 删除附件 现场铭牌.jpg`、`赵主管 将附件 报价单.pdf 设为仅销售和主管可见`。
v1.1 新增的记录文字示例：`赵主管 定价 ¥1,800`、`王敏 建议价格 ¥1,500`、`李工 申请暂停搁置（等备件：轴承预计周五到）`、`赵主管 同意暂停申请 → 暂停搁置（等备件：轴承预计周五到）`、
`赵主管 恢复处理 → 处理中`、`赵主管 添加协助人 王工`、`李工 申请添加协助人 王工`、`王敏 记录客户寄出（顺丰 SF1234567890）`、`陈工 工厂收货 → 处理中`。

进度条 5 阶段（销售首页、工单详情）：待认领=1、待启动=2、处理中=3、待验收=4、已闭环=5（服务端给 `progressStep`）。
**暂停搁置不再并入「处理中」**：暂停时停在暂停前的那一段（2 或 3），该段显示为灰色暂停样式，并显示原因文字 `暂停 · 等备件：…`；状态标签与列表也显示「暂停搁置」及原因。

## 4. 打卡与工时规则（核心）

1. 只有 `serviceType = Onsite`（现场）工单需要打卡；远程/返厂不打卡。
2. 打卡必须现场拍照（只允许相机，不允许相册），照片带水印：类型、时间、日期星期、地址、经纬度、`姓名 · 工单号`。水印由小程序端用 canvas 合成。
3. **时间以服务器为准**（服务器取北京时间，忽略客户端时间）。
4. **到场/离场由系统自动判断**：
   - 该工程师最后一条打卡是本工单的「到场」且是今天 → 下一次为「离场」。
   - 否则为「到场」。
   - 如果该工程师今天在**另一张**工单有未离场的到场 → 拒绝本次打卡，提示「请先在〈客户〉离场打卡」。
   - 前一天及更早的未配对到场 = **缺卡**（不阻止新的打卡，标记给主管补录）。
5. 中途离开现场也打离场卡，回来再打到场卡（一天可多对）。
6. 距离：服务器用 Haversine 计算打卡坐标与客户坐标（建单时地图选点，GCJ-02）的距离，**> 1000 m 标记「距离异常」，只标记不拦截**。
7. 工时 = 离场 − 到场，按「到场—离场」配对累加；配对归属到场当天。今天未离场的到场计入「现场计时中」，实时显示但不落库。
8. 首页「今日现场工时」= 今日所有已配对时长 + 正在计时的时长；首页显示 `H:mm` 大字 + `:ss` 小字（前端每秒刷新）。
9. 「出差第 N 天」= 截止今天连续有到场打卡的天数（今天有到场才显示）。
10. 「本月出差天数」= 本月有到场打卡的不同天数。
11. 页面显示到分钟（`H:mm`）；导出按小时保留 1 位小数。
12. 主管补录：只能补录缺失的那一张卡（通常是离场），必须填原因；记录补录人、补录时间；打卡记录、工时、导出中单独标注「主管补录」。补录后系统重新计算工时，缺卡问题消失。

13. **多人打卡（v1.1）**：负责人和协助人都可以在现场单上打卡，以上全部规则按**工程师本人**分别计算（各自的到场/离场、各自的未离场限制、各自的距离标记与缺卡、各自的工时）。任一参与人首次到场即让工单进入处理中。

### 异常（issues）
以下异常覆盖工单上所有打卡人（负责人、协助人、已退出的人），详情里标明是谁。
- `MissingPunch` 缺卡：存在早于今天、没有配对离场的到场卡。
- `DistanceAbnormal` 距离异常：存在 outOfRange 的打卡（主管可看照片判断，不影响闭环）。
- 「确认闭环」在存在 `MissingPunch` 时禁用，提示「请先补录缺卡」。

## 5. 完工提交

必填：现场确认的故障原因、解决措施、设备运行状况（`Normal` 正常 / `Observe` 待观察 / `NotRecovered` 未恢复）、处理照片 ≥ 1 张（需包含维修前原状）、客户签字件（现场单必填 ≥1；远程/返厂选填）。选填：更换备件。
前置条件：只有负责人可提交；状态为处理中（暂停搁置时须先恢复）；现场单不能处于「现场计时中」（负责人今天有未离场的到场 → 提示「请先离场打卡」；
任何其他参与人今天未离场 → 提示「{姓名}还在现场计时，请其先离场打卡后再提交完工」）；返厂单须已记录「寄回客户」。
提交后进入「待验收」，主管确认后闭环（须无缺卡且已定价；返厂单未记录客户签收只提示不拦截）。

## 6. 新建工单字段（SOP 记录必备要素）

类型：工单来源*（销售转报/客户直联/现场巡检/退货物流）、问题类型*（设备故障/客诉投诉/退回返修/咨询指导）、紧急程度*（紧急/一般/咨询）、维修类型*（现场/远程/返厂，只有现场需要打卡）。
客户：客户单位*、联系人*、联系电话*、客户地址*（地图选点 `wx.chooseLocation`，现场单必须有经纬度）。
设备：设备型号*、设备编号*、购买/SAT 时间*（年月 + 是否已签字）、项目编号（选填）。
故障：发生时间*（文本，如「11月4日 下午」，前端用日期+时段选择器生成）、故障现象/报错*（按客户原话）、客户已尝试的操作*、现场环境条件*、客户诉求与限制（选填）。
附件：照片 / 视频 / 文件（选填，最多 20 个，见 §12）。**建单没有价格字段**（任何角色都一样），新单为「未定价」，见 §9。
产品阶段：SAT 已签字 = 老产品，否则 = 新产品（详情页显示）。
工单号：`SH-yyyyMMdd-NNN`（当日 3 位流水，从 001 开始）。
提交后发布到工单大厅（状态 Pending）。紧急单发钉钉群提醒（配置了 webhook 时）。

## 7. 通知
`INotifier` 接口，`DingTalkRobotNotifier` 实现（配置 `DingTalk:Webhook` 时启用，否则 no-op 记日志）。触发：新建紧急单、指派/改派（提醒被指派人）、提交完工（提醒主管）。
v1.1 新增：暂停申请 / 协助人申请 / 价格建议（提醒主管）；申请被同意或驳回（提醒申请人）；工单暂停 / 恢复（提醒负责人与协助人）；被安排为协助人（提醒协助人）；
返厂客户寄出（提醒负责人）、工厂收货与寄回客户（提醒建单人）。**通知是发到群里的，正文一律不写金额**（工程师不能看到价格）。

## 9. 价格（v1.1）
- 建单不填价格。价格只由**主管**在工单详情里设置 / 修改（小程序与电脑后台都可以）；0 = 保内免费。
- 「未定价」与 0 元是两回事：工单有 `PriceSet` 标记，新单为未定价；升级前已有的工单全部视为已定价。
- **销售**能看到价格，可以给主管提「价格建议」（金额 + 选填备注），不能自己定价。主管定价时能看到最新一条建议，可一键采用。
- **工程师永远看不到价格**：接口不给工程师返回价格、价格建议与价格类状态记录（列表、详情、首页、打卡返回都一样），工程师端界面没有任何价格。
- 未定价的工单不能确认闭环（提示「请先设置服务价格（保内填 0）」）。导出（仅主管）保留价格列，未定价显示「未定价」。

## 10. 多人协作（v1.1）
- 每张工单 1 名**负责人**（即原来的处理人）+ 最多 5 名**协助人**。协助人必须是启用的工程师，且不是负责人。
- 主管在指派 / 改派时可同时选协助人，之后也可以在详情页增减（小程序与电脑后台）。负责人可以**申请**添加协助人（选人 + 选填说明），主管同意或驳回。
- 协助人：在首页 / 我的工单里能看到该单（带「协助」标签），能打开详情，现场单可到场 / 离场打卡，工时算在自己名下。
- 只有负责人能预约、开始处理、提交完工、申请暂停、申请协助人。
- 任何参与人还在现场计时：不能提交完工、不能暂停、不能把此人移除、（负责人）不能被改派。
- 缺卡覆盖所有参与人，任何一人的缺卡未补录都不能闭环。
- 改派给当前的协助人：此人转为负责人，并从协助人中移除。
- 详情页「处理人员」列出每个人及各自工时；工时统计与导出按人列出（协助人的工时计入协助人）；台账导出增加「协助人」「人员工时」列。

## 11. 返厂流程（v1.1）
维修类型为「返厂」的工单，在现有状态之内增加 5 个节点的物流时间线（返厂单不打卡）：

| # | 节点 | 谁记录 | 内容 | 对状态的影响 |
|---|---|---|---|---|
| 1 | 客户寄出 | 建单人（销售）、负责工程师、主管 | 快递公司 + 单号（必填），备注 | 无 |
| 2 | 工厂收货 | 负责工程师、主管 | 至少 1 张照片（外观 / 配件），备注 | 待启动 → 处理中（取代返厂单的「开始处理」） |
| 3 | 检测/维修 | —（隐含：收货后到寄回前） | 维修结果在完工表单里填 | 无 |
| 4 | 寄回客户 | 负责工程师、主管 | 快递公司 + 单号（必填），至少 1 张照片 | 无（之后才能提交完工） |
| 5 | 客户签收 | 建单人（销售）、负责工程师、主管 | 签收凭证照片、备注（都选填） | 无 |

- 必须按顺序记录：2 需要 1（只有主管可以跳过 1 直接记 2），4 需要 2，5 需要 4。
- 提交完工要求已记录节点 4。节点 5 在寄回之后、闭环之前随时可记；闭环不强制，未记录时主管会看到提示。
- 每个节点保存操作人、时间、字段和照片，并写一条状态记录；录错可以由同样有权限的人更正（闭环 / 作废后不可改）。
- 所有角色的工单详情都显示这条时间线（谁、何时、快递公司与单号——点单号可复制、照片），并把「下一步」按钮给到有权限的人；电脑后台的详情同样显示并可由主管操作。
- 升级前已在处理中的返厂单没有节点记录：由主管补记「工厂收货」后继续。

## 12. 工单附件与文件中心（v1.2）

### 附件
- 工单除图片、视频外可以带文档：Word（.doc/.docx）、Excel（.xls/.xlsx）、PPT（.ppt/.pptx）、PDF、.txt、.csv。其他类型（可执行文件、脚本、HTML、SVG、压缩包等）一律拒绝，服务端按扩展名 + 文件内容双重校验。
- 大小：图片 ≤ 20 MB，视频与文档 ≤ 100 MB。每张工单最多 20 个附件；升级前的「建单照片」并入同一个附件列表并计入 20 个。
- 保留原始文件名（清洗后）与大小；磁盘上的文件名是随机串。图片、视频按**原文件**保存与预览（小程序选图用原图，不压缩）。
- **建单时**：原来的「现场照片 / 视频」改为「附件（照片 / 视频 / 文件）」。小程序里文档只能从微信聊天中选（`wx.chooseMessageFile`），界面提示「先把文件发到『文件传输助手』再选择」；电脑后台用普通文件选择（可多选、可拖入）。
- **建单后**：建单人、负责人、协助人、主管可在工单详情里继续添加——除「已作废」外的任何状态；工单「已闭环」后只有主管能添加或删除。
- **删除**：上传人可删自己上传的（工单未闭环 / 未作废时），主管可删任何附件。删除是软删除（磁盘文件保留）。上传、删除、改可见范围都写状态记录。
- **仅销售和主管可见**：每个附件一个标记。销售和主管上传时可以勾选，主管之后可以切换；工程师不能设置。工程师从任何接口（详情、下载、文件中心、状态记录）都拿不到受限附件——与价格同等严格；工程师自己上传的附件被设为受限后本人也看不到。
- **查看**：图片 / 视频原地预览；文档在小程序里先下载再用 `wx.openDocument` 打开（右上角菜单可转发 / 保存；TXT、CSV 微信不支持预览，改为转发到聊天），电脑后台按原始文件名下载。
  下载走带鉴权的 `GET /api/files/{id}/download`（按可见性判权，`Content-Disposition` 带 UTF-8 文件名）；原有的 `/uploads/...` 静态地址保持可用。
- 详情页（小程序三种角色、电脑后台抽屉）都有「附件」区：名称、类型角标、大小、上传人、时间、受限标记、操作（预览 / 打开、删除、设为仅销售和主管可见）以及「添加」，带上传进度与逐个文件的错误提示。
  界面只按服务端给的 `canAddAttachment`、`canRestrictAttachment`、`attachments[].canDelete / canToggleRestricted` 显示操作，不自行推导规则。
- 完工照片、签字件、打卡照片、返厂照片、头像的规则不变（只允许图片 / 视频、20 MB）。

### 工单文件中心
- 电脑后台（主管）新增「文件」页：列出所有工单名下的文件——附件、建单照片、完工照片、签字件、打卡照片、返厂照片（不含头像）。
  列：缩略图 / 类型角标、文件名、来源、工单号 + 客户（点击打开工单抽屉）、上传人、时间、大小、受限标记。筛选：关键字（文件名 / 工单号 / 客户）、类型（图片 / 视频 / 文档）、来源、上传人、日期范围；分页；显示总数与总大小。
  操作：预览（图片 / 视频）、下载原文件、打开工单、删除与改可见范围（仅附件，规则同上）。不做批量下载。
- 所有工单文件在挂载时都已写入 `StoredFiles.OrderId`，文件中心是文件表与工单表的一个关联查询，不改动任何已有数据。
- 小程序本期没有全局文件中心，入口是每张工单详情里的「附件资料」；工程师与销售本期不能访问文件中心接口（后端查询已按角色处理可见性，便于以后开放）。
- 「公司资料库」（与工单无关的独立文档库，方案 B）本期不做；数据模型与上传 / 下载接口已为它留出扩展点（CHANGES-v1.2 §10）。

### 运维
- 上传接口的请求体上限为 101 MB；**nginx 站点的 `client_max_body_size` 必须从 30m 改为 110m**（见 `deploy/README.md`），否则大文件会被 nginx 拒绝。小程序附件上传 / 下载超时 10 分钟，电脑后台上传超时 15 分钟。
- 附件按原文件保存，`uploads/` 增长会变快，需关注磁盘空间与备份。
- 小程序后台「用户隐私保护指引」需手工新增声明项 **「选中的文件」**（`wx.chooseMessageFile`），然后重新提审发布；后端与电脑后台可先上线，v1.1 小程序不受影响。
