# 霍桐售后工单小程序 — 设计说明

来源：`售后工单小程序 原型.html`（已解包到 `docs/prototype/*.html`，含完整样式；`docs/prototype-text/*.html` 为去样式后的纯结构/逻辑版）
以及《售后服务 SOP V1.0》。接口契约见 `docs/API.md`，**前后端都必须严格按 API.md 实现**。

## 1. 总体架构

```
售后小程序/
├── docs/                 设计、接口契约、原型
├── miniprogram/          微信小程序（原生 WXML/WXSS/JS，无构建步骤）
└── server/               .NET 8 Web API（ASP.NET Core + EF Core，默认 SQLite，可切 SQL Server/MySQL）
```

- 小程序：原生框架，基础库 ≥ 3.0。自定义 tabBar（按角色显示不同按钮）。
- 后端：ASP.NET Core 8 Web API，JWT 认证，EF Core 8，默认 SQLite（零配置可跑），文件存本地 `uploads/` 并以静态文件提供。
- 主管电脑后台（原型第 17 页，1440 宽）：本期只实现其**接口**（`/api/admin/*`），网页端 UI 后续单独做。

## 2. 角色

| 角色 | Role 值 | 小程序底部导航 | 能做什么 |
|---|---|---|---|
| 售后工程师 | `Engineer` | 首页 / 工单(大厅) / **打卡**(中间凸起) / 工时 / 我的 | 认领、预约、到场离场拍照打卡、完工提交、新建工单(客户直联) |
| 销售 | `Sales` | 首页 / 工单(全部，只读) / **新建** / 我的 | 新建工单、跟踪自己提交的工单、查看全部工单(只读) |
| 售后主管 | `Supervisor` | 首页(时间轴+待办) / 工单(全部) / **新建** / 我的 | 指派/改派、作废、暂停搁置/恢复、退回、确认闭环、补录打卡、导出、账号管理 |

账号由主管在后台登记（姓名、手机号、角色、部门）。首次使用：微信登录 → 手机号快速验证 → 按手机号匹配员工 → 绑定 openid → 设置头像（可跳过）。之后自动登录。更换微信需主管解绑。

## 3. 工单状态机

| 状态 | 值 | 中文 | 进入方式 |
|---|---|---|---|
| 待认领 | `Pending` | 待认领 | 新建工单后发布到工单大厅 |
| 待启动 | `Accepted` | 待启动 | 工程师认领 / 主管指派 |
| 处理中 | `InProgress` | 处理中 | 现场单：首次到场打卡自动进入；远程/返厂单：工程师点「开始处理」 |
| 暂停搁置 | `OnHold` | 暂停搁置 | 主管从「处理中」标记（等待客户/备件/外部），可恢复为处理中 |
| 待验收 | `Submitted` | 待验收 | 工程师提交完工 |
| 已闭环 | `Closed` | 已闭环 | 主管确认闭环（存在未补录的缺卡时禁止） |
| 已作废 | `Voided` | 已作废 | 主管从「待认领/待启动」作废 |

允许的流转：
- Pending → Accepted（claim / assign）；Pending → Voided（void）
- Accepted → InProgress（首次到场打卡 / start）；Accepted → Voided；Accepted 改派（assignee 变更，状态不变）
- InProgress → Submitted（complete）；InProgress → OnHold（hold）；InProgress 改派
- OnHold → InProgress（resume）
- Submitted → InProgress（reject，退回处理中）；Submitted → Closed（close）

每次流转写一条状态记录（StatusLog）：操作人、动作文字、时间、目标状态。示例文字：`王敏 建单`、`王敏 建单 · 紧急`、`李工 认领 → 待启动`、`赵主管 指派给 王工 → 待启动`、`李工 首次到场 → 处理中`、`李工 提交完工 → 待验收`、`赵主管 补录离场 18:20`、`赵主管 确认闭环 → 已闭环`。

进度条 5 阶段（销售首页）：待认领=1、待启动=2、处理中/暂停搁置=3、待验收=4、已闭环=5。

## 4. 打卡与工时规则（核心）

1. 只有 `serviceType = Onsite`（现场）工单需要打卡；远程/返厂不打卡。
2. 打卡必须现场拍照（只允许相机，不允许相册），照片带水印：类型、时间、日期星期、地址、经纬度、`姓名 · 工单号`。水印由小程序端用 canvas 合成。
3. **时间以服务器为准**（服务器取北京时间，忽略客户端时间）。
4. **到场/离场由系统自动判断**：
   - 该工程师最后一条打卡是本工单的「到场」且是今天 → 下一次为「离场」。
   - 否则为「到场」。
   - 如果该工程师今天在**另一张**工单有未离场的到场 → 拒绝本次打卡，提示「请先在〈客户〉离场打卡」。
   - 前一天及更早的未配对到场 = **缺卡**（不阻止新的打卡，标记给主管补录）。
5. 中途离开现场也打离场卡，回来再打到场卡（一天可多对）。
6. 距离：服务器用 Haversine 计算打卡坐标与客户坐标（建单时地图选点，GCJ-02）的距离，**> 1000 m 标记「距离异常」，只标记不拦截**。
7. 工时 = 离场 − 到场，按「到场—离场」配对累加；配对归属到场当天。今天未离场的到场计入「现场计时中」，实时显示但不落库。
8. 首页「今日现场工时」= 今日所有已配对时长 + 正在计时的时长；首页显示 `H:mm` 大字 + `:ss` 小字（前端每秒刷新）。
9. 「出差第 N 天」= 截止今天连续有到场打卡的天数（今天有到场才显示）。
10. 「本月出差天数」= 本月有到场打卡的不同天数。
11. 页面显示到分钟（`H:mm`）；导出按小时保留 1 位小数。
12. 主管补录：只能补录缺失的那一张卡（通常是离场），必须填原因；记录补录人、补录时间；打卡记录、工时、导出中单独标注「主管补录」。补录后系统重新计算工时，缺卡问题消失。

### 异常（issues）
- `MissingPunch` 缺卡：存在早于今天、没有配对离场的到场卡。
- `DistanceAbnormal` 距离异常：存在 outOfRange 的打卡（主管可看照片判断，不影响闭环）。
- 「确认闭环」在存在 `MissingPunch` 时禁用，提示「请先补录缺卡」。

## 5. 完工提交

必填：现场确认的故障原因、解决措施、设备运行状况（`Normal` 正常 / `Observe` 待观察 / `NotRecovered` 未恢复）、处理照片 ≥ 1 张（需包含维修前原状）、客户签字件（现场单必填 ≥1；远程/返厂选填）。选填：更换备件。
前置条件：状态为处理中；现场单不能处于「现场计时中」（今天有未离场的到场 → 提示「请先离场打卡」）。
提交后进入「待验收」，主管确认后闭环。

## 6. 新建工单字段（SOP 记录必备要素）

类型：工单来源*（销售转报/客户直联/现场巡检/退货物流）、问题类型*（设备故障/客诉投诉/退回返修/咨询指导）、紧急程度*（紧急/一般/咨询）、维修类型*（现场/远程/返厂，只有现场需要打卡）。
客户：客户单位*、联系人*、联系电话*、客户地址*（地图选点 `wx.chooseLocation`，现场单必须有经纬度）。
设备：设备型号*、设备编号*、购买/SAT 时间*（年月 + 是否已签字）、项目编号（选填）。
故障：发生时间*（文本，如「11月4日 下午」，前端用日期+时段选择器生成）、故障现象/报错*（按客户原话）、客户已尝试的操作*、现场环境条件*、客户诉求与限制（选填）。
价格与照片：服务价格*（质保期内填 0 → 显示「保内免费」/「保内」）、现场照片/视频（选填，最多 9 个）。
产品阶段：SAT 已签字 = 老产品，否则 = 新产品（详情页显示）。
工单号：`SH-yyyyMMdd-NNN`（当日 3 位流水，从 001 开始）。
提交后发布到工单大厅（状态 Pending）。紧急单发钉钉群提醒（配置了 webhook 时）。

## 7. 通知
`INotifier` 接口，`DingTalkRobotNotifier` 实现（配置 `DingTalk:Webhook` 时启用，否则 no-op 记日志）。触发：新建紧急单、指派/改派（提醒被指派人）、提交完工（提醒主管）。

## 8. 视觉规范（取自原型）
- 页面背景 `#F6F6F4`；卡片白底 `#FFFFFF`，圆角 16px（大卡 20px），阴影 `0 1px 2px rgba(0,0,0,.04), 0 4px 14px rgba(0,0,0,.04)`。
- 主文字 `#1D1D1F`；次文字 `#6E6E73`；三级 `#AEAEB2`；分割线 `#ECECEA`；描边 `#E3E3E1`；浅底 `#F0F0EE`。
- 品牌红 `#C81E2B`（紧急、处理中、计时中），浅红底 `#FBEDEE`；成功绿 `#2F7A4B`；警示琥珀 `#9A5B00`（待认领、补录）。
- 主按钮黑底 `#1D1D1F` 白字，高 52px，圆角 10–12px；禁用 `#C7C7C5`。
- 状态标签配色：待认领 `#F0F0EE/#9A5B00`、待启动 `#F0F0EE/#636366`、处理中 `#FBEDEE/#C81E2B`、暂停搁置 `#ECECEA/#636366`、待验收 `#F0F0EE/#1D1D1F`、已闭环 `#F0F0EE/#2F7A4B`、已作废 `#F0F0EE/#AEAEB2`。
- 紧急标签 `#FBEDEE/#C81E2B`；一般 `#F0F0EE/#3A3A3C`；咨询 `#F0F0EE/#636366`。
- 数字（计时、工时、价格）使用等宽数字 `font-variant-numeric: tabular-nums`，字重 600–700。
- 头像：有头像显示图片，没有则显示姓氏单字圆形（浅灰底）。
- 原型 px 按 1px = 2rpx 换算（390 宽设计稿 ≈ 750rpx 时 1px≈1.923rpx，统一按 2rpx 即可）。
